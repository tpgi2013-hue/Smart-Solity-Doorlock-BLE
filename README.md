# Solity Doorlock (BLE) — Home Assistant 커스텀 통합

솔리티(SOLITY) 도어락의 **블루투스팩(BL-100C)** 에 Home Assistant의 블루투스 프록시를 거쳐 **직접** 연결해 여닫는 통합입니다. 클라우드·WiFi 모듈을 거치지 않아서 빠르고(연결 대기 중이면 명령 후 약 0.5초), 인터넷이 끊겨도 동작합니다.

클라우드 API 방식 통합은 별도 저장소 [Smart-Solity-Doorlock](https://github.com/tpgi2013-hue/Smart-Solity-Doorlock)에 있으며, 이 통합과 서로 독립적입니다.

## 기능

- 🔓 **잠금 / 열기** — `lock` 엔티티. 열림 직후 9초간 `해제`로 표시한 뒤(도어락 자동 잠김 대기) 실제 상태를 다시 읽어 맞춥니다.
- 📊 **상태 센서** (블루투스로 직접 읽음, 기본 30분 주기)

  | 센서 | 내용 |
  |---|---|
  | 배터리 | % |
  | 등록 카드 수 / 등록 비밀번호 수 / 등록 리모컨 수 / 마스터 카드 수 | 도어락이 보고하는 개수 |
  | 시스템 모드 | 도어락 시스템 모드 값 |
  | 보조 래치 | 1 = 문 닫혀 걸쇠 걸림, 0 = 문 열림 |
  | 신호 세기 | 프록시가 받은 도어락 RSSI (dBm) |

  잠김/해제(`lock` 상태)는 **데드볼트** 값을 씁니다. 지문·얼굴·정맥 등록 수는 이 도어락이 블루투스로 보고하지 않아 제공하지 않습니다.
- ⏳ **연결 대기 스위치** — 켜면 도어락과 미리 연결·인증해 두고 명령을 기다립니다. 그 상태에서 오는 열기 명령은 연결 수립(약 1~3초)을 건너뜁니다. 끄면 즉시 연결을 끊고, 열기/잠그기 명령 후나 **20초 상한**에서는 스스로 꺼집니다.

## 요구 사항

- 도어락에 **솔리티 블루투스팩** 장착
- Home Assistant **블루투스**(로컬 어댑터 또는 ESPHome 블루투스 프록시) — 도어락이 연결 가능한 거리에 있어야 함
- 도어락 **블루투스 MAC 주소**
- **앱 키** — 도어락 소유자(마스터) 계정의 `regDeviceAppKey` (base64). 구성원 계정에는 없습니다.

## 설치

**HACS**: HACS → 사용자 지정 저장소 → `https://github.com/tpgi2013-hue/Smart-Solity-Doorlock-BLE` (유형: 통합) 추가 후 설치, HA 재시작.

**수동**: `custom_components/solity_ble` 폴더를 HA 설정 폴더의 `custom_components/` 아래에 복사하고 HA 재시작.

## 설정

설정 → 기기 및 서비스 → 통합 추가 → **Solity Doorlock (BLE)**

| 항목 | 예 |
|---|---|
| 이름 | 현관 도어락 (BLE) |
| 블루투스 MAC | `AA:BB:CC:DD:EE:FF` |
| 앱 키 | base64 문자열 |

옵션에서 **상태 조회 주기**(분, 0 = 끔)를 바꿀 수 있습니다. 주기가 짧을수록 블루투스 접속이 잦아져 도어락 배터리를 더 씁니다.

## 예: 현관 재실 센서로 연결 대기

재실이 켜지면 연결 대기를 켜고, 꺼지면 바로 끊습니다. 엔티티 이름은 환경에 맞게 바꾸세요.

```yaml
alias: 현관 도어락 BLE 연결 대기
mode: queued
triggers:
  - trigger: occupancy.detected
    target:
      entity_id: binary_sensor.front_door_presence
    id: presence_on
  - trigger: state
    entity_id: binary_sensor.front_door_presence
    to: "off"
    id: presence_off
actions:
  - choose:
      - conditions:
          - condition: trigger
            id: presence_on
        sequence:
          - action: switch.turn_on
            target:
              entity_id: switch.hyeongwan_doeorag_ble_connection_standby
      - conditions:
          - condition: trigger
            id: presence_off
        sequence:
          - action: switch.turn_off
            target:
              entity_id: switch.hyeongwan_doeorag_ble_connection_standby
```

연결 대기는 도어락과 연결을 유지하는 동안 배터리를 씁니다. 문 앞 통행이 많은 곳이라면 재실 감지 거리를 줄이는 것이 좋습니다.

## 동작 방식 (프로토콜 요약)

GATT 서비스 `48400001-…`, 쓰기 `48400002-…`, 알림 `48400003-…`.
프레임 `48 <len> <cmd> <data…> <checksum>`, AES-128-CBC.

1. `0x10` 키 교환(평문) → `0x90` 수신 키
2. 세션 IV = 앱 키 앞 8바이트 + 수신 키 앞 8바이트
3. `0x11` 앱 인증 → `0x91` 결과 0
4. `0x21` 열기 / `0x22` 잠그기 / `0x51` 상태 요청 → `0xA1` / `0xA2` / `0xD1`

도어락은 이미 원하는 상태일 때 명령을 `result=1`로 거부합니다(예: 잠긴 상태에서 잠그기). 통합은 이때 상태를 다시 읽어, 이미 그 상태면 오류 없이 끝냅니다.

## 변경 이력

### 1.3.1
- "예열" 명칭을 **연결 대기**로 변경 (스위치 이름, 오류 문구, 문서). 동작 변화 없음.

### 1.3.0 — 연결 대기 스위치 (당시 이름: 예열)
- 예열 **버튼 → 스위치**로 변경. 켜면 연결 유지, 끄면 즉시 해제, 열기/잠그기 후 또는 20초 상한에서 자동으로 꺼짐.
- 재실 센서와 묶어 "문 앞에 사람이 있는 동안만" 연결을 유지할 수 있게 됨. 고정 시간 예열이 얼굴인식 순간에 끝나며 생기던 실패를 없앰.

### 1.2.0 — 실패 처리와 상태 정확도
- 명령이 실패(거부 포함)하면 1.1초 뒤 **새 연결로 한 번 재시도**.
- 열기/잠그기가 거부되면 상태를 다시 읽어, 이미 그 상태면 오류 없이 종료하고 표시를 실제 값으로 맞춤.
- 상태 조회 결과가 `해제`면 15초마다 다시 읽음(최대 8회). 문을 쓰는 순간 조회된 `해제`가 다음 정기 조회까지 남던 문제 해결.
- 예열 유지 10초 → 8초.

### 1.1.1
- 예열 유지 20초 → 10초.

### 1.1.0 — 연결 예열
- **연결 예열 버튼** 추가: 미리 연결·인증해 두고 일정 시간 유지. 예열 상태의 열기는 약 0.5초(예열 없을 때 약 3.5초 이상).
- 명령 후 상태 프레임 대기 시간 2.5초 → 0.4초. HA 표시와 응답이 약 2초 빨라짐.

### 1.0.0 — 첫 버전과 초기 다듬기
- 블루투스 프록시 경유 **열기/잠그기** (클라우드 통합과 분리된 독립 통합).
- 상태 조회 코디네이터와 센서(배터리, 데드볼트, 등록 수, 시스템 모드, 보조 래치), 아이콘, 조회 주기 옵션.
- 상태 요청을 `0x51`로 수정(응답 `0xD1`).
- 항상 0/알 수 없음이던 얼굴·정맥·지문 등록 수 센서 제거, 비밀번호 등록 수와 신호 세기(RSSI) 센서 추가.
- 블루투스 출입 기록(`0x5D`) 읽기를 시도했으나 이 도어락은 기록을 비워 둬서 되돌림(이력에 남아 있음).

이전 이력은 [Smart-Solity-Doorlock](https://github.com/tpgi2013-hue/Smart-Solity-Doorlock) 저장소의 `custom_components/solity_ble` 경로에서 개발되었고, 이 저장소로 커밋 이력 그대로 옮겨왔습니다.
